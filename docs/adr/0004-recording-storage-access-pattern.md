# Recordings use a private R2 bucket with direct presigned uploads and signed-URL playback

`Recording` files are stored in a private Cloudflare R2 bucket rather than a public one, and uploads go straight from the client to R2 via a Django-issued presigned PUT URL rather than being proxied through the Django app server. We considered public objects with permanent URLs (simpler, no signing logic) and a proxied upload through Django (simpler, one endpoint), but rejected both: public objects would expose rehearsal audio outside the club with no benefit, conflicting with the map's privacy-by-design principle, and proxied uploads would route large audio files from mobile connections through Render's free-tier app server, which is the more resource-constrained hop. Direct presigned uploads and short-lived signed URLs for playback are standard `django-storages`/S3-compatible-backend features, so the added complexity is minimal.
