# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code under `frontend/`.

A React/TypeScript single-page app under `frontend/`, built by Vite into `frontend/dist/` and served by `config/views.py:SpaIndexView` — a Django view that reads Vite's `manifest.json` per request and emits the hashed script/style tags it names, never a static `index.html`. Every non-`/admin/`, non-`/accounts/`, non-`/api/` path falls through to it (`config/urls.py`'s catch-all), and the SPA renders its own 404 client-side for anything its own route table (`frontend/src/routes.tsx`) doesn't claim. Issue #341 replaced the entire server-rendered Django template tree, its twelve hand-rolled vanilla-JS files, and the vendored Pico/HTMX/Alpine/SortableJS stack with this in one cutover PR — no feature flag, no coexistence period, `git log` is the only record of the old implementation. ADR 0012 records the decision and exactly how far it reverses issue #168 (no bundler) and issue #123 (no DRF).

- **A bundler and a node toolchain are now present and pinned** — `frontend/package.json` + a committed `frontend/package-lock.json`, `npm ci` before every build, `.nvmrc` pinning the Node version. This reverses #168's no-bundler call; unlike the vendored stack it replaces, it comes with ordinary Dependabot visibility rather than a manual download-and-rename bump.
- **No CDN, still — this prohibition did not reverse.** It was decided on privacy grounds, not tooling grounds: this is an auth-gated portal for a named group, and a CDN would announce every member's IP and referer to a third party on every page load. That reasoning doesn't care what assembled the page, so it survives the stack change intact. `scheduling/tests/test_static_assets.py` fails the build the moment any built page or stylesheet references an off-origin `src`/`href`/`url()` — including a webfont pulled from a font host at CSS-parse time, the likeliest way a CDN would re-enter.
- **DRF is still rejected, on the same reasoning as #123** — now proven rather than merely argued: the seam for a future API is `scheduling/services.py`/`identity/services.py`, endpoint-per-interaction, and the migration built exactly that without needing a resource-shaped HTTP layer on top of the ORM.
- **Testing**: Vitest + React Testing Library, at the route-component level, against a mocked fetch layer — asserting rendered structure and interaction, never component internals or a real network call. `npm run test` runs the suite; CI's node job also runs `npm run lint`, `npm run format:check`, `npm run typecheck` and `npm run build`.
- **Static serving**: `STATIC_ROOT`/WhiteNoise is unchanged, but `STATICFILES_DIRS` now has two entries — the (now largely empty) top-level `static/` and `frontend/dist` as its own physically separate entry, so Vite's `assets/` subdirectory can never shadow anything else's filenames. Nothing serves the built assets unless the deploy build runs `npm ci && npm run build` **before** `collectstatic`; that ordering is `build.sh` and CI's `build` job, and `config.checks.spa_build_output_exists` fails `manage.py check --deploy` (only `--deploy`, never a plain `manage.py test`) if the manifest is missing.
- The Django admin stays mounted as the low-level escape hatch for the long tail the custom UI doesn't cover, and `identity/people.html` (`/accounts/manage/people/`) survives outside the SPA as the same class of thing — a low-level escape hatch this ticket deliberately did not migrate (see the Route shape bullet in the root `CLAUDE.md`).
